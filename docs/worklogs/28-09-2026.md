# Worklog 28/09/2026

Continues [[26-09-2026]] on `feature/langgraph-rewrite`.

## Motion replay label = the prompt Kimodo rendered

**Request:** the motion replay list (desktop dropdown + mobile chips) named each motion by the user's raw chat message. Name it by the prompt the agent sent to Kimodo instead.

**Why it needed backend work:** that prompt is the planner's `resolved_query` (kimodo.py hashes it into `job_id` and enqueues it as `prompt`), but it never left the backend — the SSE `motion` event carried only state/job_id, and `messages.extras` stored only `{"motion": {"job_id"}}`.

**Change:**
- `nodes/kimodo.py`: `prompt` added to the three payloads that carry a job_id (cache_hit, queued-dedup, queued). busy/unavailable unchanged.
- `api/main.py`: captures `motion_prompt` next to `motion_job_id`, passes it to `write_session_turn`.
- `db/session_store.py`: new trailing kwarg `motion_prompt`; stored as `extras.motion.prompt` (no migration, JSONB); `_shape_message` returns `motion_prompt` only when stored.
- Frontend `api.ts` / `ChatContext.tsx` / `MotionContext.tsx`: label = `m.prompt` live, `motion_prompt` on restore; falls back to the user's message for sessions saved before this change.
- Planner keeps `resolved_query` in the user's language, so Vietnamese users still get Vietnamese labels, just cleaned up ("động tác squat").

**Tests:** kimodo node, SSE capture, write-path signature (the "motion_job_id must be the last param" assertion rewritten to what its comment meant: every param from it onward has a default), batching extras, `_shape_message`.
