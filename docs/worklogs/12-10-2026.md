## ADR-007 — BYOK for the LLM

Decided with Tri on 11–12/10.

- A user's own provider key is used **instead of ECA's key** for the turn's LLM
  steps (planner, retriever, synthesizer). ECA does not store it: the browser
  keeps it in localStorage and sends it in the `/chat` body each turn; the
  server holds it in memory for that request only.
- One adapter for every provider: `ChatOpenAI` + `base_url`, the way DeepSeek
  was already wired. No provider table in the backend. The frontend's preset
  list only prefills an endpoint.
- No dependency on OpenRouter; it is one preset among others.
- The connection check runs in the browser, straight to the provider, when the
  key is pasted. Metadata first (models.dev), then a single ping. No separate
  JSON probe.
- A graph role runs on the user's model only if the model can do what that role
  asks. A model that only reads and writes text still writes the answer.
- Not in this round: sending images to the model; localhost models (waits for
  a desktop build).

Chosen by K, not yet confirmed by Tri: the safety grader and the background
summarizer stay on ECA's key; a provider failure mid-turn falls back to ECA
with a notice; the preselected model is the cheapest of the five newest.

## Second round: the provider list comes from the catalog

After Tri's second test. Commit `a2ec7e08`, then `c3217838` (merge, below).
Three statements above no longer hold: the typed model name for a provider
with no list is gone, the logos are no longer "26 of 28 presets", and the test
count has moved.

Decision (Tri, 12/10): 26 hand-copied cards are hardcoding. The list is read
from models.dev; "OpenAI Compatible" stays.

- `catalogProviders()` in `modelCatalog.ts`. Three rules, none a list of names:
  1. the catalog says the provider speaks chat completions (`npm` is
     `@ai-sdk/openai-compatible`) at one fixed https address: 226 → 177;
  2. an entry whose name says "Coding" or "Plan" is left out: 19. Alibaba's
     Coding Plan terms forbid using the key from "application backends". The
     other companies' plans are hidden by name; their terms were not read;
  3. one card per address: 1 dropped.

  157 cards from the catalog on 12/10.
- `LLM_PRESETS` keeps 14 visible hand-written entries: "OpenAI Compatible" and
  the 13 providers the catalog names without a chat address (it records only
  their own SDK). Ollama and LM Studio stay behind the backend's local flag.
  Featherless, Atlas Cloud, CometAPI, n1n and OpenPaths are not in the catalog
  and were removed. Local logo files remain for hand-written entries only; a
  catalog card uses `https://models.dev/logos/<id>.svg`.
- Caught by no rule: OpenCode Go, GitHub Copilot, ClinePass. The catalog has no
  field for "approved clients only". Left visible.
- A search box; cards with a saved key come first.
- API key screen: nothing is saved until "Use this API key" is pressed (Tri's
  rule). The typed model name is removed.
- Model picker: models that cannot hold a chat are left out, with a count.
  These are the ones a provider serves over another API format (per-model
  `provider.npm`) and the ones that do not take text and answer in text: 120
  of the 6,385 models under the listed providers.
- A provider that lists models to a web page but refuses the chat address
  (OpenCode: preflight 404) cannot be sent a trial message from the browser.
  The key is still confirmed: the listing refuses a made-up key (401) and took
  the user's. What the model can do then comes from the catalog. The model
  itself stays untested until the first chat turn.
