# 31-10-2026 — Avatar emotion follows the query and the action

> Branch: `local-testing-improve` (fast-forwarded to `origin/feature/langgraph-rewrite` @ 30f9f84)
> | Plan: [[avatar-emotion-context]] (`docs/plans/avatar-emotion-context.md`)

## Summary

The face now reacts to the user's message while the avatar thinks, smiles
lightly while demonstrating an exercise, shows a brief "sorry" when a motion or
the turn fails, and rests on a warm face after a reply instead of blank
neutral. The FSM's per-state `facial` policy, declared but never read before,
is now applied. Tri's idle rule (relaxed only, 50–60 s apart) is untouched.

## Changes

### Task 0 — measure the reply tag
- `nodes/synthesizer.py` `send_emotion()` logs one `reply_emotion` line per
  reply: `picked` (raw tag), `sent` (after health rules), `missing`. A reply
  with no tag at all logs `missing: true` at stream end.
- **Still to do:** read 2–3 days of prod logs; if >20 % missing, fix the prompt.

### Task 1 — FSM facial policy
- `lib/AnimationStates.ts`: new `FacialPolicy { wander, hold?: {name, intensity}, action? }`.
  thinking_intro/loop → neutral 1 (yields to the turn's face);
  thinking_outro → no hold (was neutral: would wipe a reply that arrived mid-loop);
  exercise → happy 0.35, `action` (covers the turn's face, gives it back after);
  gesture → no hold (its face track + reaction emotion already own the face).
- New `avatar/TurnFace.ts`: pure rules for which face a turn shows
  (state hold < listening face < reply; an action hold wins while it plays).
- `avatar/AvatarController.ts`: `beginTurn`, `setReplyEmotion`,
  `setListeningEmotion`, `applyFacialPolicy`. A hold counts as engaged, so the
  idle wanderer / engaged→idle fade cannot change the face underneath.
  `setThinking` no longer sets neutral itself (the policy does).
- `contexts/MotionContext.tsx`: applies `facialOf(state)` on every state change.

### Task 2 — listening face from the query
- `nodes/planner.py`: `user_affect` field (`pain|worry|sad_news|thanks|greeting|good_news|neutral`)
  in the same structured call; prompt section + all 11 examples; unknown → neutral.
- `state.py`: `user_affect: str`. `api/main.py`: forwarded on the planner `stage` event.
- `lib/replyEmotion.ts`: `listeningFace()` (pain/worry/sad_news → sad 0.3;
  thanks/greeting/good_news → happy 0.4), `isSafetyTurn()`.
- `contexts/ChatContext.tsx`: `beginTurn()` on send; planner stage →
  `setListeningEmotion` (safety tags → neutral); reply `emotion` → `setReplyEmotion`.
- `docs/architecture/sse-contract.md`: `user_affect` documented.

### Task 3 — outcome faces
- Motion `unavailable` / `busy` / failed to play, and turn `error` → sad 0.25
  (`SETBACK_FACE`), back to the resting face after the 3 s engagement grace.
- **Not done:** approval-gate face. There is no approval gate in the frontend
  or backend today (grep: no `approv` in either), so nothing to hook.

### Task 4 — warm resting face
- Engaged → idle now fades to `relaxed 0.2`, or neutral after a safety turn.
  Binary-morph emotions fall back to neutral (`applyFace`).

## Intensity guard
Every new face is ≤ 0.5 (exercise 0.35, listening 0.3/0.4, setback 0.25,
resting 0.2), so a model's `overrideMouth/Blink/LookAt: block` cannot mute
lip-sync, blink or the thinking glance. Test enforces it on the state table.
