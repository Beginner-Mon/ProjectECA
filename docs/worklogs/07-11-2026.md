# 07-11-2026 — Water-fill loading screen

> Branch: `local-testing-improve`. Request (Tony): replace the round spinner
> with the ECA logo filling with water on black; the water should creep up
> slowly and surge to full when loading finishes (not track bytes).

## Changes
- `components/ui/LoadingOverlay.tsx` rewritten: black screen, faint empty logo,
  two wave layers (brand gradient) drifting inside the logo shape. New
  `active` prop: when it turns false the water surges to full (650 ms),
  settles with a small bob (450 ms), then the logo grows slightly and the
  overlay fades out (450 ms) and unmounts itself.
- `lib/waterFill.ts` (+ tests): slow rise `0.85 · (1 − e^(−t/6 s))`, never
  reaching the top; one fill clock per page load so the app-start loader
  (AuthGuard) hands its level to the avatar loader instead of draining.
- `CharacterViewer.tsx`: loader kept mounted, `active={!viewerReady || isAvatarSwitching}`.
  AuthGuard unchanged (its loader is replaced in the same render; the shared
  clock keeps the level).
- `lib/ecaLogo.ts`: logo path/viewBox/transform shared; `EcaLogo.tsx` uses it.
- `App.css`: logo mask (`public/eca-logo.svg`), `water-drift`, `water-settle`
  keyframes; all off under `prefers-reduced-motion`.

## Performance
Only CSS transforms on ordinary elements (HTML layers + an outer `<svg>` per
wave), masked by CSS — eligible for compositor animation, so the water should
keep moving while the main thread parses the avatar. No canvas, no second WebGL
context, no per-frame JS. The old spinner's `backdrop-blur` over the 3D canvas
is gone (solid black), which removes a per-frame blur.
Not measured with a performance trace — design-based.
